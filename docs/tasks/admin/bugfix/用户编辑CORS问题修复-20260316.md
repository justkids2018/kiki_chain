# 用户编辑功能 CORS 问题修复

**问题时间**: 2026-03-16
**问题**: 用户管理编辑后无法保存

---

## 🐛 问题描述

用户在管理后台编辑用户信息后，点击"保存"按钮无法成功保存数据。

## 🔍 问题诊断

### 1. 后端 API 测试
使用 curl 直接测试后端 API，发现 API 本身工作正常：

```bash
curl -X PATCH http://127.0.0.1:8081/api/v1/admin/users/test_user_003/update \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Test Update"}'

# 响应
{"success":true,"data":{"uid":"test_user_003"},"message":"更新成功"}
```

### 2. 前端代码检查
前端代码逻辑正确，使用了正确的 API 调用方式。

### 3. CORS 配置检查
发现问题：**后端 CORS 配置中缺少 PATCH 方法**

**原配置**:
```rust
.allow_methods([Method::GET, Method::POST, Method::PUT, Method::DELETE])
```

**问题**: 没有包含 `Method::PATCH`，导致浏览器的 CORS 预检请求失败。

---

## ✅ 解决方案

### 修改文件
`kiki_server/src/adapters/http/middleware.rs`

### 修改内容
在 CORS 配置中添加 PATCH 方法：

```rust
.allow_methods([Method::GET, Method::POST, Method::PUT, Method::PATCH, Method::DELETE])
```

### 完整代码
```rust
pub fn create_cors_layer(allowed_origins: Vec<String>) -> CorsLayer {
    let origins: Result<Vec<HeaderValue>, _> = allowed_origins
        .into_iter()
        .map(|origin| origin.parse())
        .collect();

    match origins {
        Ok(origins) => CorsLayer::new()
            .allow_origin(origins)
            .allow_methods([Method::GET, Method::POST, Method::PUT, Method::PATCH, Method::DELETE])
            .allow_headers([header::CONTENT_TYPE, header::AUTHORIZATION, header::ACCEPT])
            .allow_credentials(true),
        Err(e) => {
            Logger::warn(format!("CORS配置错误: {}", e));
            CorsLayer::permissive()
        }
    }
}
```

## 📊 问题根因分析

### CORS 工作原理
1. 浏览器发送跨域请求前，会先发送 OPTIONS 预检请求
2. 预检请求询问服务器是否允许该方法和头部
3. 如果服务器响应允许，浏览器才会发送实际请求
4. 如果服务器不允许，浏览器会阻止请求并报错

### 为什么 curl 可以但浏览器不行？
- **curl**: 不执行 CORS 检查，直接发送请求
- **浏览器**: 出于安全考虑，强制执行 CORS 策略

### 常见的 HTTP 方法
- **GET**: 获取资源
- **POST**: 创建资源
- **PUT**: 完整更新资源
- **PATCH**: 部分更新资源 ⚠️ 容易被遗漏
- **DELETE**: 删除资源

## 🎯 最佳实践

### 1. CORS 配置建议
在开发环境中，建议包含所有常用的 HTTP 方法：

```rust
.allow_methods([
    Method::GET,
    Method::POST,
    Method::PUT,
    Method::PATCH,
    Method::DELETE,
    Method::OPTIONS,  // 预检请求
])
```

### 2. 前端 API 设计
- **POST**: 创建新资源
- **PUT**: 完整替换资源（需要提供所有字段）
- **PATCH**: 部分更新资源（只提供需要更新的字段）✅ 推荐用于编辑功能

### 3. 调试技巧
当遇到跨域问题时：
1. 打开浏览器开发者工具 → Network 标签
2. 查看是否有 OPTIONS 预检请求
3. 检查预检请求的响应头
4. 确认 `access-control-allow-methods` 是否包含所需方法
