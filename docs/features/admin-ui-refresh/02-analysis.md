# Kiki 管理后台 UI 升级现状分析

## 结论

需求边界已确认：只借鉴参考图的视觉表达，Kiki 的架构、业务逻辑与数据契约保持独立。现状允许在不改 API 的前提下，通过公共壳层与用户页样式完成第一阶段升级。

## 现有实现

- 技术栈：Vue 3、TypeScript、Vue Router、Element Plus、局部 scoped CSS。
- 公共框架：`views/Layout.vue` 同时承载菜单、顶部栏、路由出口与退出登录。
- 用户页面：`views/Users.vue` 直接调用 `api/users.ts`，提供列表、前端搜索、详情和编辑。
- API 契约：`docs/api/endpoints/admin.md` 已定义用户列表、详情和更新接口，本次无需修改。
- 全局样式：`src/style.css` 仍保留 Vite 模板样式，且当前未由 `main.ts` 引入，缺少后台专用设计变量。

## 视觉差异

| 维度 | 现状 | 目标方向 |
|---|---|---|
| 导航 | 200px 深色侧栏 | 轻量浅色侧栏、清晰选中态、支持收起 |
| 顶部栏 | 仅标题和用户名 | 明确页面定位、紧凑账户入口 |
| 内容层级 | 灰底加默认卡片 | 淡蓝灰画布、白色功能面板、克制阴影 |
| 筛选区 | 标题与搜索同一行 | 标题说明、独立筛选工具条、重置与刷新 |
| 表格 | 默认边框表格 | 紧凑行高、弱分隔线、稳定列宽与截断 |
| 操作 | 默认蓝色和橙色按钮 | 统一圆角与层级，查看次级、编辑主操作 |

## 复用点与影响面

- 复用现有路由元信息、菜单定义、认证退出逻辑、用户 API 和表单校验。
- 直接影响 `Layout.vue` 和 `Users.vue`，新增或重写后台全局样式入口。
- 公共壳层会改变其他后台页面的外围视觉，但不改其内部 DOM 和业务行为。

## 风险

- 公共样式覆盖 Element Plus 可能影响其他页面。缓解：使用 `.kiki-admin` 命名空间和局部页面类。
- 用户数据无分页接口。第一阶段保持前端筛选，不伪造服务端分页能力。
- 旧页面在新画布下可能显得不一致。缓解：公共壳层先兼容，后续逐页迁移。
- 侧栏收起会改变内容宽度。缓解：固定状态模型与 1280px、窄窗口截图验证。

## 文档差异

- 不涉及 API 变更，`docs/api/endpoints/admin.md` 无需修改。
- 需新增后台视觉设计与任务拆分，交付后补充验证、审查和文档收口记录。
