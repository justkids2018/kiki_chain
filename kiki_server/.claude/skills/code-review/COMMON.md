# 通用代码审查规范 (Common Code Review Standards)

> **适用范围**: 所有编程语言和项目
> **版本**: v1.0
> **最后更新**: 2026-01-19

本文档定义了**跨语言通用**的代码审查标准和检查清单。

---

## 📋 审查检查清单（15 项）

### 1. 功能完整性 ✅
- [ ] 所有需求的功能都已实现
- [ ] 没有遗漏的 TODO
- [ ] 没有注释掉的代码（除非有说明）
- [ ] 所有引用的资源都存在

### 2. 准确性 ✅
- [ ] 代码逻辑符合架构设计
- [ ] 数据模型实现正确
- [ ] 业务逻辑准确无误
- [ ] 命名规范统一

### 3. 可测试性 🧪
- [ ] 关键逻辑有测试用例
- [ ] 边界条件有测试覆盖
- [ ] 错误情况有测试验证

### 4. 可复用性 ♻️
- [ ] 没有重复代码（DRY 原则）
- [ ] 组件/函数职责单一（SRP）
- [ ] 魔法数字/字符串已常量化

### 5. 一致性 📏
- [ ] 代码风格一致
- [ ] API 命名风格统一
- [ ] 错误处理方式统一
- [ ] 日志格式统一

### 6. 设计合理性 🏗️
- [ ] 没有过度设计
- [ ] 没有性能瓶颈
- [ ] 数据结构设计合理
- [ ] 算法效率可接受

### 7. 错误处理 ⚠️
- [ ] 所有可能的异常都已捕获
- [ ] 错误信息清晰明确
- [ ] 错误不会导致崩溃
- [ ] 记录足够的错误日志

### 8. 数据安全 🔐
- [ ] 没有 SQL 注入风险
- [ ] 没有 XSS 风险
- [ ] 敏感数据已加密
- [ ] 输入数据已验证
- [ ] 权限控制正确

### 9. 注释与文档 📝
- [ ] 复杂逻辑有注释说明
- [ ] 公共 API 有文档注释
- [ ] 关键算法有说明
- [ ] 特殊处理有原因说明

### 10. 性能优化 ⚡
- [ ] 没有不必要的计算
- [ ] 循环优化合理
- [ ] 数据库查询优化
- [ ] 避免内存泄漏
- [ ] 资源正确释放

### 11. 依赖管理 📦
- [ ] 新依赖有必要性说明
- [ ] 依赖版本明确
- [ ] 没有循环依赖
- [ ] 依赖安全性检查

### 12. 代码风格 🎨
- [ ] 缩进一致
- [ ] 命名清晰
- [ ] 格式统一
- [ ] 符合项目规范

### 13. 边界条件 🔍
- [ ] 空值处理
- [ ] 极端值处理（最大/最小）
- [ ] 并发情况处理
- [ ] 异常情况处理

### 14. 架构原则 🧩
- [ ] 遵循 SOLID 原则
- [ ] 依赖方向正确（内层不依赖外层）
- [ ] 职责分离清晰

### 15. 可维护性 🔧
- [ ] 代码易读
- [ ] 结构清晰
- [ ] 容易扩展
- [ ] 容易调试

---

## 📊 评分标准

### 优秀（90%+）
- 所有 Critical 项通过
- 绝大多数 Warning 项通过
- 代码规范、注释完整、性能优秀

### 良好（70-89%）
- 所有 Critical 项通过
- 部分 Warning 项需要修复
- 整体不错，小问题可以修复后合并

### 需改进（<70%）
- 存在 Critical 问题
- 多个 Warning 问题
- 需要重构或大幅修改

---

## ⚠️ 常见问题分类

### Critical（必须修复）
- 编译错误
- 安全漏洞（SQL 注入、XSS）
- 崩溃风险（panic、未处理异常）
- 数据丢失风险
- 权限控制错误

### Warning（应该修复）
- 性能问题
- 代码规范违反
- 缺少关键注释
- 错误处理不完善
- 内存泄漏风险

### Suggestion（可以改进）
- 代码优化
- 重构建议
- 命名改进
- 结构调整
