# Sherpa-ONNX TTS 体积与架构优化方案（仅文字转语音）

## 1. 背景与目标

本项目当前需求只有 TTS（文字转语音），不包含 STT（语音转文字）。

目标：

1. 保持现有 TTS 功能与体验（中英文朗读）
2. 显著降低模型与资源体积，减少 APK 包体和安装耗时
3. 明确哪些文件必须保留、哪些可以删除、哪些不应打入 APK
4. 形成可执行的分阶段优化方案

---

## 2. 官网用法结论（针对当前需求）

基于 sherpa-onnx 官方文档（TTS/VITS/Piper）：

1. TTS 只需要 Offline TTS 相关模型与配置，不需要 ASR/STT 组件。
2. 中文 VITS 常见最小必需项是：model.onnx + tokens + lexicon（可选规则 FST）。
3. 英文 Piper 常见必需项是：onnx + tokens + espeak-ng-data。
4. 官方示例中，规则 FST 仅在需要数字/日期等文本规范化时显式传入。
5. aishell3 官方示例（icefall 版本）模型文件口径约 29MB（仅 onnx 文件）。
6. 文档中常见的“xx MB”通常是单模型文件口径，不是整套中英双模型总口径。

---

## 3. 现状盘点（本项目）

### 3.1 功能范围

当前代码仅使用 TTS，未接入 STT/ASR。

### 3.2 当前模型与大文件（LFS）

当前 LFS 追踪的大文件：

1. en_US-amy-low.onnx：63MB
2. vits-aishell3.onnx：121MB
3. vits-aishell3.int8.onnx：40MB
4. rule.far：181MB

合计约 405MB。

### 3.3 当前资源打包方式

pubspec 中对 tts_models 声明较宽，包含大量目录级资源，导致会把较多内容打包到产物。

### 3.4 实现层关键结论

1. 当前中文配置使用 vits-zh-aishell3，模型文件名为 vits-aishell3.onnx。
2. 当前引擎配置中 ruleFsts 为空字符串（默认不使用规则 FST）。
3. 英文模型校验逻辑只强依赖少量核心文件（并非整个 espeak-ng-data 全量目录都必需）。

---

## 4. 为什么会出现“官方看起来 100MB 左右，但本地 400MB+”

1. 口径不同：官方多为单模型文件口径，本地是双语模型 + 冗余文件总口径。
2. 冗余共存：中文同时保留了 fp32 与 int8 两份 onnx。
3. 额外大文件：rule.far 体积很大，但当前默认并未启用。
4. 打包范围偏宽：pubspec 目录声明过大，容易把本可按需处理的资源一并打包。
5. 本地仓库体积放大：.git/lfs 与 .git/objects 也会占大量磁盘，不等于 APK 体积。

---

## 5. 可删除/可迁移清单

## 5.1 可优先删除（低风险）

1. rule.far（181MB）
   - 理由：当前默认未启用规则 FST。
2. vits-aishell3.int8.onnx（40MB）
   - 理由：当前默认走 fp32 模型；若无 int8 切换逻辑，可先移除。

预估可立减约 221MB。

## 5.2 可迁移（不打入 APK）

1. 英文模型（63MB）
   - 方案：改为首次使用英文时按需下载，中文继续内置。
2. 非核心 espeak 语言资源
   - 方案：仅保留运行必要子集，其他放在线资源包或安装后下载。

## 5.3 需要评估后再动

1. 中文模型替换为更轻版本（例如 icefall aishell3 29MB 口径）
   - 需同步改模型文件名、元数据和兼容性验证。

## 6. 推荐优化路线（分阶段）

## 阶段 A：快速瘦身（建议先做）

目标：不改交互逻辑，仅减少无效体积。

执行：

1. 删除未启用的 rule.far。
2. 删除未使用的 vits-aishell3.int8.onnx。
3. 收紧 pubspec 资产声明为“精确文件列表”，避免目录级全量打包。

预期：

1. 模型体积从约 405MB 降至约 184MB 左右。
2. 风险低，改动可控。

## 阶段 B：结构优化（中文内置 + 英文按需）

目标：进一步压首包。

执行：

1. 首包仅内置中文 TTS。
2. 英文模型改按需下载与缓存。
3. 提供下载状态提示与失败重试机制。

预期：

1. 首包再降约 60MB+。
2. 英文首次使用有一次下载等待。

## 阶段 C：模型升级优化

目标：在保证音质前提下继续减重。

执行：

1. 评估并替换中文模型为更轻版本。
2. 做音质、稳定性与儿童音色需求回归。

预期：

1. 中文模型可显著减小。
2. 需要更多测试投入。

---

## 7. 第一优先动作（你问的“首先做什么”）

先做阶段 A。

原因：

1. 立刻见效（可直接降 200MB 级别）
2. 业务影响最小（不改变功能边界）
3. 可以快速验证“体积问题主要来自冗余文件，而不是 STT 模块”

---

## 8. 验收标准

1. 功能验收
   - 中文朗读正常
   - 英文朗读正常
   - 点击区域、整词朗读、单字朗读行为不回退

2. 体积验收
   - 模型目录总量下降
   - 构建产物中的 tts 相关资源体积下降

3. 稳定性验收
   - 首次初始化可用
   - 无模型路径错误
   - 无空音频生成错误

---

## 9. 风险与应对

1. 风险：删除文件后路径校验失败
   - 应对：先做最小文件清单，再跑全量回归

2. 风险：按需下载引入网络不稳定
   - 应对：本地缓存 + 失败重试 + 回退提示

3. 风险：更轻模型音色不符合儿童场景
   - 应对：做音色 A/B 对比并保留可回退模型

---

## 10. 建议的最终架构（适配当前需求）

1. 首包只放中文核心 TTS（高频场景）
2. 英文模型按需下载并缓存
3. 模型资源统一放独立目录并做版本管理
4. 代码层只保留 TTS 能力，不引入 STT 相关依赖

## 12. 术语白话解释（看不懂英文时可先看这里）

下面把文档里常见缩写和英文词，按“逐词 + 白话”的方式解释。

1. TTS = Text To Speech
   - Text：文本
   - To：转换为
   - Speech：语音
   - 白话：把文字读出来。

2. STT = Speech To Text
   - Speech：语音
   - To：转换为
   - Text：文本
   - 白话：把人说的话识别成文字。

3. ASR = Automatic Speech Recognition
   - Automatic：自动
   - Speech：语音
   - Recognition：识别
   - 白话：自动语音识别。通常和 STT 是一类能力。

4. Offline
   - 直译：离线
   - 白话：不连网也能运行。

5. Model
   - 直译：模型
   - 白话：AI 的核心数据文件，通常体积最大。

6. VITS
   - 说明：一种常见的语音合成模型架构名。
   - 白话：TTS 引擎的一种“发声方案”。

7. Piper
   - 说明：一个常见的 TTS 模型/生态名称（在 sherpa-onnx 里可用于英文语音）。
   - 白话：另一种可用的发声模型体系。

8. onnx
   - 说明：模型文件格式（Open Neural Network Exchange）。
   - 白话：模型本体常见后缀，像 vits-aishell3.onnx。

9. lexicon
   - 直译：词典
   - 白话：发音词典，告诉模型某些词怎么读。

10. tokens
   - 直译：符号/标记
   - 白话：模型识别和发音时用的字符映射表。

11. FST / rule.far
   - FST：Finite State Transducer（有限状态转换器）
   - rule.far：规则文件包
   - 白话：做数字、日期等文本规范化的规则资源；不用规则时可不启用。

12. espeak-ng-data
   - 说明：英文语音常用的发音数据目录。
   - 白话：英文模型发音需要的配套字典/音素数据。

13. APK
   - 全称：Android Package
   - 白话：Android 安装包。

14. 包体 / package size
   - package：包
   - size：大小
   - 白话：安装包有多大。你提到的 paper weights，大概率是 package size 或包体 weight 的误写。

15. fp32 / int8
   - fp32：32 位浮点精度
   - int8：8 位整数量化精度
   - 白话：同一个模型的两种精度版本。int8 更小更省资源，音质可能略有差异。

16. LFS（Git LFS）
   - 全称：Large File Storage
   - 白话：Git 管理大文件的方式，避免仓库被大文件直接塞爆。

17. sid（speaker id）
   - speaker：说话人
   - id：编号
   - 白话：选音色/说话人的编号。

18. fallback
   - 直译：回退
   - 白话：主方案失败时自动切换到备选方案。

19. cache
   - 直译：缓存
   - 白话：把下载或生成过的文件先存起来，下次更快。

20. 你们当前需求一句话版
   - 当前只做 TTS：点文字就朗读。
   - 当前不做 STT：不需要把用户说话转成文字。

## 14. 代码级优化方案（分步可落地）

### 14.1 第一步（马上做，低风险）

目标：不改功能行为，只减体积。

改动清单：

1. 收紧 kiki_web/pubspec.yaml 的 assets 声明
   - 删除目录级全量声明，改为精确文件白名单。
   - 尤其删除 espeak-ng-data/lang 下大量未用语言族目录声明。

2. 只保留当前运行必需文件
   - 中文：vits-aishell3.onnx、tokens.txt、lexicon.txt
   - 英文：en_US-amy-low.onnx、tokens.txt、espeak 必需 7 个核心文件
   - 可以先移出：rule.far、vits-aishell3.int8.onnx（若无切换逻辑）

3. 增加构建前校验脚本（建议）
   - 在 scripts 下增加一个 tts 资源校验脚本，检查白名单文件是否齐全。
   - 防止误删后运行时报缺文件。

预期收益：

1. 体积立减，且不改变你们现有朗读逻辑。
2. 代码风险最低。

### 14.2 第二步（你提到的公共目录方案）

目标：把当前项目不常用模型放公共目录，项目只保留常用模型。

建议落地：

1. 公共目录定义
   - 选对象存储或 CDN 作为公共模型目录。
   - 目录结构与当前模型目录保持一致，避免改动过大。

2. 项目内策略
   - 首包只带中文模型。
   - 英文模型改为首次点英文时下载并缓存到 Documents/sherpa_onnx。
   - 下载失败时给用户提示，并允许重试。

3. 代码改造点
   - kiki_web/lib/core/speech/model_download_manager.dart
     - 把 download 从禁用改为可用（仅英文启用）。
     - 增加文件校验和、版本号校验。
   - kiki_web/lib/core/speech/local_speech_service.dart
     - 英文引擎初始化时，先检查本地，再触发下载。
     - 下载中返回可感知状态（用于 UI 提示）。

预期收益：

1. 首包明显减小。
2. 保留中文离线体验。

### 14.3 第三步（可选，持续优化）

目标：继续压体积并平衡音质。

可选动作：

1. 评估中文模型换轻量版。
2. 或增加模型开关：默认 int8，必要时回切 fp32。

## 15. 方案比对结论（给决策用）

| 决策问题 | 推荐答案 |
|---|---|
| 现在先做什么 | 先做 S1（白名单 + 删除未用大文件） |
| 公共目录要不要做 | 要做，但放到 S2，先中文内置、英文按需 |
| STT 模型要不要放公共目录 | 目前不需要，项目当前没有 STT 功能 |
| 什么时候做模型替换 | 等 S1/S2 稳定后再做 S3 级别优化 |

一句话建议：

先把包内无效内容清掉，再把英文模型迁到公共目录按需下载，这样收益最大且风险可控。
