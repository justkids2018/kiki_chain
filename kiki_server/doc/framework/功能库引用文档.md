# 功能库引用指南（2025）

> 更新时间：2025-08-15  
> 说明：文档基于 Stage5 清理后的目录结构，辅助快速定位各层可复用功能。关注点：哪些库可直接复用？引用时有哪些注意事项？

---

## 1. 模块地图

```
src/
├── core/            # 业务内核（实体、值对象、端口、用例）
├── adapters/        # 技术实现（HTTP / Postgres 等）
├── framework/       # 启动 & 组合（日志、依赖注入、路由）
├── config/          # 环境配置加载与校验
├── shared/          # 跨层共享结构（API 响应）
└── utils/           # 通用工具（JWT、HTTP、错误别名等）
```

本文主要覆盖可复用的 **工具库 (utils)**、**共享库 (shared)**、**框架公共能力 (framework/logging & bootstrap)** 与 **依赖注入流程**，帮助快速引用。

## 2. Utils 工具库

### 2.1 错误与返回类型

- 位置：`src/utils/errors.rs`
- 功能：统一的 HTTP 层错误类型，承载 `IntoResponse` 实现。
- 主要类型：
  - `pub type Result<T>`：HTTP 统一返回类型。
  - `pub enum Error`：常见业务 / 系统错误枚举，自动映射到合适的 HTTP 状态码。
- 使用方式：

```rust
use crate::utils::errors::{Error, Result};

fn handler() -> Result<()> {
    Err(Error::Validation("手机号格式不正确".into()))
}
```

> 注意：`core` 层请使用 `core::errors::Result`/`DomainError`，由适配层转换到此错误类型。

### 2.2 JWT 工具

- 位置：`src/utils/jwt.rs`
- 职责：封装 `jsonwebtoken`，负责令牌生成、验证、解析。

```rust
use crate::utils::{JwtConfig, JwtUtils};

// 启动时初始化（可通过 quick_init 读取默认配置）
JwtUtils::quick_init()?;

// 手动配置
JwtUtils::init(JwtConfig {
    secret: "your-secret".into(),
    expiration_hours: 24,
})?;

// 生成 / 校验
let token = JwtUtils::generate_token(&user)?;
let claims = JwtUtils::verify_token(&token)?;
```

常见调用点：
- `core/use_cases/auth/login_user.rs`：生成登录令牌。
- 中间件：解析 `Authorization` 头部，提取用户 ID。

### 2.3 HTTP 工具

- 位置：`src/utils/http.rs`
- 功能：处理 HTTP 请求头与常用解析逻辑（示例：从 `HeaderMap` 抽取用户 ID）。
- 示例：

```rust
use crate::utils::HttpUtils;

let user_id = HttpUtils::extract_user_id_from_headers(&headers)?;
```

### 2.4 通用工具

- 位置：`src/utils/tool.rs`
- 内容：密码哈希 / 验证等纯工具函数。

```rust
use crate::utils::ToolUtils;

let hash = ToolUtils::hash_password("plain")?;
let ok = ToolUtils::verify_password("plain", &hash)?;
```

## 3. Shared 跨层共享

### API 响应包装

- 位置：`src/shared/api_response.rs`
- 功能：统一成功 / 失败响应结构，并提供基于 `DomainError` 的转换。

```rust
use crate::shared::ApiResponse;
use serde_json::Value;

let success = ApiResponse::success(Value::Null, "操作成功");
let failure = ApiResponse::from_domain_error(&domain_error);
let status = failure.http_status();
```

> Tips：`from_domain_error` 会自动映射错误码和 HTTP 状态码，控制器只需关心业务异常的传播。

## 4. Framework 公共能力

### 4.1 日志模块

- 位置：`src/framework/logging.rs`
- 提供：
  - `LogConfig` / `LogLevel` / `Logger`
  - 便捷宏：`log_info!`、`log_warn!`、`log_error!`、`log_debug!`、`log_json!`

```rust
use crate::framework::logging::Logger;

Logger::info("应用启动");
Logger::database_error("数据库连接失败");
log_info!("启动端口: {}", port);
```

初始化方式：`framework/bootstrap/mod.rs::init_logging()` 会依据 `ENVIRONMENT` 选择合适的日志级别并调用 `Logger::init`。

### 4.2 依赖注入与路由

- 位置：
  - `src/framework/bootstrap/container.rs` — 负责拼装 `AppState`
  - `src/framework/bootstrap/routes` — 统一注册路由与中间件

核心流程（`DependencyContainer::new`）：
1. 构建仓储实现（`PostgresUserRepository`）
2. 构建用例（`LoginUserUseCase` / `RegisterUserUseCase` 等）
3. 构建控制器（`AuthController`）
4. 组装 `AppState` 暴露给 Axum Router

外部使用：

```rust
use crate::framework::bootstrap::{create_routes, DependencyContainer};

let container = DependencyContainer::new(pg_pool);
let app = create_routes(container.app_state);
```

## 5. 中间件组合

- 位置：`src/adapters/http/middleware.rs`
- 支持：
  - 请求/响应日志（自动脱敏、附带 request_id）
  - 错误转换（捕获 `DomainError` → `ApiResponse`）
  - JWT 鉴权（含白名单路径）
  - CORS 配置

装配示例（`framework/bootstrap/routes/app.rs`）：

```rust
Router::new()
    .merge(health_routes)
    .merge(auth_routes)
    .layer(middleware::from_fn(jwt_auth_middleware))
    .layer(middleware::from_fn(error_handling_middleware))
    .layer(middleware::from_fn(request_response_data_log_middleware))
    .layer(create_cors_layer(config.cors_origins().to_vec()));
```

若新增业务路由，只需在 `framework/bootstrap/routes` 中组合，并复用这些中间件。

## 6. 配置系统

- 位置：`src/config/mod.rs`
- 特点：
  - 支持多环境配置（`development` / `pre-release` / `production`）
  - 环境变量优先，可覆盖配置文件
  - 自动校验 `JWT_SECRET`、`DATABASE_URL`
  - 开发环境缺省时注入安全提示

使用示例：

```rust
use crate::config::AppConfig;

let config = AppConfig::load()?;
let addr = config.server_address();
let jwt_secret = config.jwt_secret()?;
```

`config` 模块还提供 `database::get_database_pool()`，供框架层初始化连接池。

## 7. 实体与仓储（核心引用提示）

虽然本文聚焦公共功能，也补充核心模块引用要点：

- `core/entities/mod.rs`：定义 `User` 等业务实体，避免在适配层直接操作数据库返回的原始结构体。
- `core/ports/mod.rs`：声明仓储 trait；适配层的数据库实现放在 `adapters/persistence/postgres`。
- `core/use_cases/auth/`：用例暴露 `execute`，供控制器调用；返回领域 DTO 或实体。
- 适配层通过 trait 对接用例，保持依赖倒置。

> 如需新增领域能力，先在 `core` 定义实体/用例/端口，再在 `adapters` 实现接口，最后由框架层组合。

---

## 8. 使用准则

1. **保持依赖方向**：`core` 绝不引用 `adapters` / `framework`；外层调用需通过 trait/DTO。
2. **统一错误链**：核心逻辑抛出 `DomainError`，适配层接住后转换成 `utils::errors::Error` 或 `ApiResponse`。
3. **日志安全**：记录敏感字段时注意脱敏，重用 `Logger`/中间件封装。
4. **配置集中**：新增可配置项统一放入 `config/{env}.toml`，在 `AppConfig` 中暴露访问方法。
5. **工具无状态**：`utils` 保持纯函数/静态方法，便于测试和复用。

## 9. 常见场景一览

| 场景 | 使用的模块 | 关键函数 |
| --- | --- | --- |
| 登录生成 JWT | `utils::JwtUtils` | `generate_token` / `verify_token` |
| 验证密码 | `utils::ToolUtils` | `verify_password` |
| 返回统一响应 | `shared::ApiResponse` | `success` / `from_domain_error` |
| 初始化日志 | `framework::logging` | `Logger::init` / `init_logging` |
| 依赖注入 | `framework::bootstrap` | `DependencyContainer::new` |
| 新增路由 | `framework::bootstrap::routes` | `create_routes` 合并 |
| 获取配置 | `config::AppConfig` | `AppConfig::load` |

通过以上分层的功能库，系统既保持了 Clean Architecture 的依赖方向，又提供了易于复用、维护的工具箱。新增业务时先确认所属层级，再复用或扩展相应模块即可。欢迎在 Stage6 中继续补充测试与示例，以强化这套架构。***
