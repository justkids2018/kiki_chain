《Kiki漫游 · 想象力教育产品需求文档》（PRD v1.2 · 含MVP）

创建时间：2025-10-31
版本：v1.2
适用对象：产品 / 前端（Flutter）/ 后端（Rust）/ AI（Dify）/ 区块链（Substrate）

⸻

1. 背景与目标

现在大多数儿童 AI 应用是“平台给孩子内容”，孩子是被动接受的。
Kiki漫游的目标是反过来：让孩子用“自己的照片”当主角，让AI围绕她生成学习内容，这样孩子更愿意看、家长更愿意晒，产品更容易传播。

产品使命：

让孩子通过 AI 与绘画表达想象力，用简单英语说出来，并把成长过程留下来。

核心理念：
	1.	孩子是主角（从她的照片开始）
	2.	学习是看得见的（有英文、有朗读、有跟读反馈）
	3.	成果是传播得出去的（分享卡、打印涂色版）
	4.	成长是留得住的（后续上链）

⸻

2. 用户与场景

2.1 目标用户
	•	孩子（5–10岁）：喜欢看见自己、喜欢“变成公主/宇航员/小猫”、能简单跟读；
	•	家长：希望“好玩但不是纯玩”，最好能证明孩子今天确实学到一句；
	•	（后续）老师/机构：可把生成的涂色稿做成课堂素材。

2.2 使用场景
	1.	家长晚上陪孩子：拍一张 → 生成AI公主图 → 播放英文 → 孩子跟读 → 分享
	2.	家长晒朋友圈：展示孩子“自己生成的”AI英语卡
	3.	家长打印线稿：周末让孩子在线下涂色，做成成长档案

⸻

3. 产品核心流程（主线）

上传孩子照片
 → 选择/输入主题
 → AI 生成围绕她形象的插画
 → 自动生成英文（单词 + 一句英文 + 中文）
 → 播放朗读
 → 孩子跟读 → AI给简单反馈
 → 生成可分享学习卡
 → 一键生成涂色/打印版
 → （预留）把作品信息写入链上做成长记录

这条是产品唯一主线，MVP 所有功能都围绕它展开。

⸻

4. MVP 范围（这一版必须实现的）

4.1 Must Have（必须有）
	1.	上传孩子照片
	•	来源：相册 / 拍照
	•	支持简单裁剪
	•	要求清晰人像
	2.	选择/输入主题
	•	内置：公主、公主+动物、宇航员、森林、小猫、运动、魔法
	•	可输入一句想法（中/英都行），如“在海底”“pink princess”
	3.	AI 围绕孩子形象生成图片
	•	必须能看出是孩子（不能生成完全陌生的脸）
	•	儿童插画风、色彩柔和、安全
	•	出错可重试一次
	4.	自动生成英语内容
	•	至少包含：
	•	1个英文单词（与主题相关，如 princess / astronaut / cat）
	•	1句英文（≤8词，如 “She is a princess.”）
	•	1行中文解释（她是一位公主。）
	•	难度控制在 A1/A2（小学低年级可听）
	5.	英文朗读
	•	单词能读
	•	句子能读
	•	儿童语速、清晰
	6.	跟读与语音反馈（轻量版）
	•	孩子点击“我来读”录音（2~3秒自动结束）
	•	后端对比识别结果和目标句
	•	返回 3 档反馈：
	•	👍 很棒（识别到核心词）
	•	🙂 再来一次（有说，但不完整）
	•	🤔 我没听清（噪音/没说）
	•	不做复杂“口语评分分数”
	7.	一键生成可分享学习卡
	•	含：孩子的AI图像 + 英文 + 中文 + Kiki漫游标识
	•	预留二维码位置（可先写死为产品主页/下载页）
	•	可保存到相册、可走系统分享
	8.	一键生成涂色/打印版
	•	把生成的彩色图转成黑白线稿
	•	白底、线条清晰、A4比例，便于打印
	•	给家长一个按钮：“保存涂色版（打印）”
	9.	作品基础保存
	•	至少能看到“我刚刚生成的这一张”
	•	保存：图片URL + 英语JSON + 时间

⸻

4.2 Nice to Have（可后做）
	•	历史作品列表 / 成长册视图
	•	分享图带动态短链（统计谁分享的）
	•	同一主题“再生成一张”（孩子想要不同造型）

4.3 Out of Scope（本期不做）
	•	NFT / 主网上链 / 资产化
	•	教师/机构版、班级管理
	•	复杂口语测评（音素级、语调、流利度）
	•	任务化、闯关式课程

⸻

5. 三端需求

⸻

5.1 App 端（Flutter）

**目标：**让孩子和家长在 3~4 步内完成一次创作，并能听、能说、能存、能分享、能打印。

5.1.1 页面结构
	1.	首页 / 开始创作
	•	按钮：📷 上传照片
	•	下方：最近一次作品缩略图（如有）
	2.	选择主题页
	•	推荐主题列表（卡片式）
	•	输入框（自定义想法）
	3.	生成中页
	•	动画+文案：“Kiki正在帮你画出来…”
	4.	结果页（核心）
	•	顶部：生成的AI图片（孩子形象）
	•	中部“学习区”：
	•	英文单词（大号）
	•	英文句子
	•	中文解释
	•	🔊读单词 / 🔊读句子
	•	🎤我来读（录音按钮）
	•	结果提示：👍 很棒！/ 我们再试一次好不好？
	•	底部操作：
	•	【保存学习卡】
	•	【保存涂色版（打印）】
	•	【分享】
	5.	作品列表页（可后做）
	•	按时间列出生成过的作品
	•	支持重新分享/重新打印

5.1.2 交互要求
	•	生成失败要有“再生成一次”
	•	录音失败要有“周围有点吵，我们再来一次”提示
	•	分享走系统分享
	•	保存打印版时给出 toast：“已保存到相册，可打印”

5.1.3 前端技术点
	•	图片上传（相册/拍照）
	•	音频录制并上传
	•	TTS 播放
	•	保存图片到相册
	•	调系统分享
	•	预览打印版

⸻

5.2 服务端（Rust / API）

**目标：**把“生成、打分、分享图、涂色图、存储、上链（预留）”这些事都接起来，给前端一个简单的API。

5.2.1 API（示例）
	•	POST /api/upload
入参：图片文件
出参：图片URL
	•	POST /api/generate
入参：图片URL + 主题
出参：{ image_url, english_json }
	•	POST /api/speech-score
入参：音频 + 目标句
出参：{ level: "good|ok|retry", tips: "..." }
	•	GET /api/artworks?user_id=...
出参：作品列表
	•	GET /share/{artwork_id}
用于分享落地页（H5）

5.2.2 功能模块
	1.	AI调用模块
	•	和 Dify 通信
	•	负责：把照片+主题 → AI图；主题 → 英文
	•	失败重试
	2.	图片处理模块
	•	合成分享图（彩色）
	•	彩图 → 线稿（打印）
	3.	语音打分模块
	•	调ASR识别音频
	•	和目标句简单对比
	•	给出3档结果
	4.	数据存储模块（PostgreSQL）
	•	users
	•	artworks（user_id, image_url, sketch_url, english_json, created_at, chain_hash）
	5.	区块链模块（预留）
	•	生成作品哈希
	•	调用 Substrate 写入
	•	返回 TxHash
	•	异步，不阻塞前端

⸻

5.3 AI / 运营端（Dify）

**目标：**控制生成的图“像孩子”、风格统一、词句简单。

5.3.1 Flow
	1.	图像生成Flow
	•	输入：孩子照片URL + 主题
	•	Prompt 固定：儿童插画、柔和、安全、保留孩子脸、不要文字
	•	输出：生成图URL
	2.	英语生成Flow
	•	输入：主题
	•	输出：

{
  "word": "princess",
  "sentence_en": "She is a princess.",
  "sentence_zh": "她是一位公主。"
}


	3.	（可选）审核Flow
	•	检查生成图是否失真/诡异
	•	不通过则重生

5.3.2 可配置内容
	•	主题词库
	•	英语难度
	•	分享图文案模板
	•	敏感内容过滤词

⸻

6. 打印 / 涂色版需求

**功能：**在生成彩色图的同时，一键生成用于线下打印的黑白线稿。

要求：
	•	白底
	•	线条适中（儿童彩笔能盖住）
	•	构图和原图一致（能看出是孩子）
	•	输出 PNG / JPG
	•	尺寸 A4 比例（2480×3508 px 理想）

**入口：**结果页按钮【保存涂色版（打印）】

**使用人：**家长 → 打印机 → 给孩子线下画

⸻

7. 区块链（预留）
	•	目的：给孩子的“第几次想象作品”做一个不可篡改的成长留痕
	•	技术：Substrate / Polkadot 测试网
	•	存储内容：作品哈希、创建者账号、时间戳、标题
	•	调用方式：后端生成作品后异步上链
	•	前端表现：作品详情里显示“✅ 已记录到链（测试网）”
	•	本期不做 NFT/交易

⸻

8. 时间计划（参考）

周次	工作
W1–W2	PRD确认、Flutter+Rust骨架
W3–W4	Dify 图 + 英文打通
W5–W6	前端做上传→生成→朗读→录音
W6–W7	语音反馈对接
W7–W8	分享图 + 打印版
W9–W10	上链预留接口
W11–W12	测试、内测、体验调优


⸻

9. 验收标准
	1.	一次完整体验可以走通：上传 → 生成 → 听 → 说 → 得反馈 → 保存 → 打印
	2.	生成图 80% 以上能看出是孩子
	3.	英文都能朗读
	4.	跟读反馈能正常出现3种结果
	5.	分享图保存成功
	6.	打印版能在A4上打印清楚
