## 🔑 核心API快速查看

### 场景数据流（最重要）

```
1. 启动App → GET /scene/categories
   返回：4个一级分类（春节、节气、日常、游乐）

2. 点击"春节场景" → GET /scene/categories/cat_001/scenes
   返回：5个子场景（回家、除夕、初一拜年、游园、元宵节）

3. 点击"除夕" → GET /scene/scenes/scene_002
   返回：场景详情 + 18个互动物品 + 用户学习进度

4. 学习物品后 → POST /user/learning-records
   提交：已学习物品ID列表 + 学习时长
```

### 用户登录流程

```
1. 注册 → POST /auth/register
   返回：用户信息 + Token

2. 登录 → POST /auth/login
   返回：用户信息 + Token

3. 自动登录 → GET /auth/verify
   验证：Token是否有效

4. 游客数据迁移 → POST /user/migrate-guest-data
   绑定：游客模式下的学习记录
```

## 📊 数据结构总览

### 核心实体关系

```
User（用户）
  ├─ 1:N → LearningRecord（学习记录）
  └─ N:M → Scene（收藏的场景）

SceneCategory（一级分类）
  └─ 1:N → Scene（二级场景）
      └─ 1:N → SceneItem（场景物品）
```

### 关键数据模型

#### SceneCategory（一级分类）
```json
{
  "id": "cat_001",
  "name": "春节场景",
  "icon": "🎉",
  "sceneCount": 5,         // 包含的子场景数
  "totalItemCount": 75     // 该分类下所有物品总数
}
```

#### Scene（二级场景）
```json
{
  "id": "scene_001",
  "categoryId": "cat_001",
  "name": "除夕",
  "itemCount": 18,
  "interactiveImage": "https://...",
  "userProgress": {        // 用户学习进度
    "learnedItems": 12,
    "progress": 0.67,
    "starCount": 2
  }
}
```

#### SceneItem（场景物品）
```json
{
  "id": "item_001",
  "text": "年夜饭",
  "textPinyin": "nián yè fàn",
  "textEnglish": "New Year's Eve Dinner",
  "coordinates": [...]    // 热区坐标
}
```

在开发前，请确认以下设计是否合理：

### 数据完整性
- [ ] 场景分类是否包含了所有需要的字段？
- [ ] 学习记录是否能准确反映用户进度？

- [ ] 是否需要分页加载？（当前：一次性返回所有分类和场景）
- [ ] 图片URL是否支持CDN？
- [ ] 是否需要增加缓存策略？

- [ ] 是否需要添加场景的"难度等级"字段？
- [ ] 是否需要添加"完成时间"字段？
- [ ] 是否需要添加"分享"功能的接口？

### 扩展性
- [ ] 如果未来场景数量很大（如1000个），现有API是否支持？
- [ ] 是否需要预留"视频/音频"资源字段？
- [ ] 是否需要支持"场景合集"（如春节礼盒套装）？

## 🤔 待确认问题

以下问题需要你决策（影响后续开发）：

1. **后端技术栈**：Node.js / Python / Go？
   - 推荐：Node.js（Express/Koa）或 Python（FastAPI）

2. **数据库选择**：MySQL / PostgreSQL / MongoDB？
   - 推荐：PostgreSQL（支持JSON字段，适合存储坐标数据）

3. **图片存储**：
   - 本地存储 / 阿里云OSS / 七牛云？
   - 推荐：七牛云（有免费额度）

4. **场景数量很大时是否分页？**
   - 当前设计：一次性返回所有场景

5. **是否需要管理后台？**
   - 用于添加/编辑/删除场景
   - 我可以帮你设计管理后台的API
