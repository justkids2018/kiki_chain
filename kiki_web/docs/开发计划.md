> 版本：v1.0

---

## 一、开发原则

### 核心原则
1. **小步快跑**：每个功能模块独立开发、测试、提交
2. **增量开发**：在现有代码基础上渐进式添加功能
3. **Mock优先**：前端先用Mock数据，后端完成后再对接
4. **功能完整**：每个迭代都要保证可运行、可演示

### 代码质量要求
- 每个功能提交前必须自测通过
- 代码遵循Clean Architecture分层
- 使用GetX状态管理（保持现有风格）
- 每次提交都要有清晰的commit message

## 四、风险与应对

### 风险1：时间超期
**应对**：
- 每个Phase完成后立即Review，及时调整
- 复杂功能可以先做简化版本
- 非核心功能可延后

### 风险2：技术难点
**应对**：
- 提前识别技术难点（如JWT、游客数据迁移）
- 遇到问题及时讨论，不要硬扛
- 可以先跳过，做其他功能

### 风险3：需求变更
**应对**：
- 每个Phase开始前确认需求
- 小步快跑，及时发现问题
- 变更需求及时更新文档
