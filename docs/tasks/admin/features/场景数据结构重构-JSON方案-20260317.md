# 场景数据结构重构 - JSON 方案实施完成

**日期**: 2026-03-17
**状态**: ✅ 已完成

## 重构概述

将场景物品数据从关系型存储（scene_items 表）改为 JSON 存储（scenes.items_data 字段），简化数据结构和管理界面。

## 数据库变更

### 1. 添加 items_data 字段
```sql
ALTER TABLE scenes ADD COLUMN items_data JSONB DEFAULT '[]'::jsonb;
```

### 2. 保留 scene_items 表
- 暂时保留，不删除（以防需要数据迁移）
- 新功能不再使用此表

## 后端变更

### 1. 实体层 (src/core/entities/scene.rs)
- `Scene` 实体添加 `items_data: Option<serde_json::Value>` 字段
- `SceneDetail.items` 改为 `Vec<serde_json::Value>`（不再使用 SceneItem）

### 2. 仓储层 (src/adapters/persistence/postgres/scene_repository.rs)
- `map_row_to_scene()`: 添加 items_data 字段映射
- `find_scene_detail()`: 从 items_data 解析物品数据，不再查询 scene_items 表
- `save_scene()`: 添加 items_data 字段保存

### 3. 用例层 (src/core/use_cases/scene/admin_scene.rs)
- `CreateSceneCommand`: 添加 `items_data` 字段
- `UpdateSceneCommand`: 添加 `items_data` 字段
- `create_scene()`: 自动计算 item_count
- `update_scene()`: 更新 items_data 时自动更新 item_count

### 4. HTTP 层 (src/adapters/http/scene/)
- `CreateSceneRequest`: 添加 `items_data` 字段
- `UpdateSceneRequest`: 添加 `items_data` 字段
- `SceneDetailDto.items`: 改为 `Vec<serde_json::Value>`
- handlers: 传递 items_data 到 use case

## 前端变更

### 1. 场景管理 (kiki_admin/src/views/Scenes.vue)
- ❌ 移除"物品"按钮
- ❌ 移除 item_count 列显示
- ✅ 添加"物品数据 JSON"文本框（支持多行编辑）

- ✅ 提交时解析 JSON 并验证格式
- ✅ 编辑时格式化显示 JSON（缩进 2 空格）

### 2. API 接口 (kiki_admin/src/api/scenes.ts)
- `Scene` 接口添加 `items_data?: any` 字段

### 3. 路由清理
- 保留 SceneItems.vue 页面（暂不删除，可能用于查看）
- 不再从场景管理跳转到物品管理

## JSON 数据格式

```json
[
  {
    "type": "chinese",
    "id": "chinese_pinyin_01",
    "index": 1,
    "text": "动物世界",
    "text_pinyin": "dòng wù shì jiè",
    "text_english": "Animal World",
    "coordinate": [
      {"x": 198, "y": 197},
      {"x": 378, "y": 197},
      {"x": 378, "y": 295},
      {"x": 198, "y": 295}
    ]
  }
]
```

## 优势

1. ✅ 管理简单：一个场景一条记录，无需管理物品关系
2. ✅ 导入方便：直接粘贴 JSON 文件内容
3. ✅ 性能提升：减少数据库查询（一次查询获取完整场景）
4. ✅ 灵活性高：JSON 结构可以随时调整，无需修改表结构
5. ✅ 前端友好：API 返回完整数据，无需多次请求

## 注意事项

1. **JSON 验证**：前端提交时会验证 JSON 格式，格式错误会提示
2. **item_count 自动计算**：后端会根据 items_data 数组长度自动计算
3. **数据迁移**：如果 scene_items 表有数据，需要编写迁移脚本
4. **向后兼容**：旧的 scene_items 表暂时保留，不影响现有数据
