## 🎯 When to Use

**自动激活条件**:
- 用户提出新功能需求（如："实现用户收藏功能"）
- 需要跨项目协调（涉及多个端）
- 项目规划和任务分解
- 查询项目状态和进度

**触发关键词**:
- "实现...功能"
- "开发..."
- "帮我规划..."
- "添加...特性"
- "创建...模块"

## 📋 Workflow / Process

### Step 1: 需求分析和理解

**目标**: 深入理解用户需求，识别涉及的端

**检查清单**:
- [ ] 复述用户需求，确认理解
- [ ] 识别功能类型（新功能/优化/修复）
- [ ] 判断涉及的端：
  - 仅后端？
  - 仅移动端？
  - 仅管理后台？
  - 后端 + 移动端？
  - 后端 + 管理后台？
  - 三端全部？
- [ ] 评估复杂度（简单/中等/复杂）
- [ ] 识别依赖关系

**智能识别规则**:
```
关键词 "用户可以..." → 移动端 + 后端
关键词 "管理员可以..." → 管理后台 + 后端
关键词 "场景"、"学习"、"进度" → 可能涉及三端
关键词 "统计"、"报表"、"批量" → 管理后台 + 后端
关键词 "API"、"接口" → 后端
关键词 "界面"、"UI" → 前端
```

### Step 2: 任务分解

**目标**: 将需求分解为具体的开发任务

**分解策略**:

1. **数据层任务**（如果需要新数据）
   - 数据库设计（表结构、索引、关系）
   - 数据迁移脚本

2. **后端任务**（如果涉及后端）
   - API 设计（端点、方法、参数、响应）
   - 业务逻辑实现
   - 权限控制
   - 单元测试

3. **移动端任务**（如果涉及 kiki_web）
   - UI 设计和实现
   - 状态管理（Controller）
   - API 集成
   - 用户体验优化

4. **管理后台任务**（如果涉及 kiki_web_manager）
   - 管理界面实现
   - 数据表格/表单
   - 批量操作
   - 数据统计

**任务优先级**:
```
P0 (阻塞性): 必须立即完成，阻塞其他任务
P1 (高优先级): 核心功能，尽快完成
P2 (中优先级): 重要但不紧急
P3 (低优先级): 优化和增强
```

### Step 3: 生成任务文件

**目标**: 创建结构化的任务文件到 docs/tasks/

**任务文件格式**:
```markdown
# [功能名称]

**优先级**: P0/P1/P2/P3
**状态**: 📝 待办 / 🚀 进行中 / 👀 审查 / 🧪 测试 / ✅ 完成
**涉及端**: 后端 / 移动端 / 管理后台
**预计时间**: X 小时
**创建时间**: YYYY-MM-DD

## 需求描述

[详细描述功能需求]

## 技术方案

### 后端
- [ ] 任务项 1
- [ ] 任务项 2

### 移动端
- [ ] 任务项 1
- [ ] 任务项 2

### 管理后台
- [ ] 任务项 1
- [ ] 任务项 2

## 依赖关系

- 依赖任务 1
- 依赖任务 2

## 自动化执行

是否允许自动执行？ [x] 是 [ ] 否

执行策略：
- [x] 自动生成契约
- [x] 自动生成代码框架
- [ ] 自动补充业务逻辑（需人工）
- [x] 自动生成测试

## 验收标准

- [ ] 标准 1
- [ ] 标准 2
```

**文件路径规则**:
- 后端任务: `docs/tasks/backend/features/[功能名]-[日期].md`
- 移动端任务: `docs/tasks/app/features/[功能名]-[日期].md`
- 管理后台任务: `docs/tasks/admin/features/[功能名]-[日期].md`

### Step 4: 协调执行

**目标**: 按照依赖关系协调各端的开发

**执行策略**:

1. **串行执行**（有依赖关系）
   ```
   后端 API 实现 → 前端集成
   数据库迁移 → 后端实现 → 前端实现
   ```

2. **并行执行**（无依赖关系）
   ```
   移动端 UI 优化 || 管理后台 UI 优化
   后端 API A || 后端 API B
   ```

**协调规则**:
- 后端 API 必须先于前端实现
- 数据库迁移必须先于后端实现
- 移动端和管理后台可以并行开发
- 契约定义必须先于代码生成

**调用其他 Skills**:
```
Phase 1: 契约定义
  → 调用 /contract-manager 创建契约

Phase 2: 代码生成
  → 调用 /code-generator 生成三端代码

Phase 3: 后端实现
  → 调用 kiki_server/.claude/skills/code-implementation
  → 调用 kiki_server/.claude/skills/code-review

Phase 4: 前端实现（并行）
  → 调用 kiki_web/.claude/skills/code-implementation
  → 调用 kiki_web_manager/.claude/skills/code-implementation

Phase 5: 集成测试
  → 生成集成测试脚本
```

### Step 5: 进度跟踪和报告

**目标**: 实时跟踪开发进度，生成报告

**跟踪内容**:
- 任务状态变化
- 完成的文件和代码行数
- 生成的测试数量
- 遇到的问题和解决方案
- 总耗时

**报告格式**:
```markdown
# 开发完成报告

## 功能概述
[功能名称和描述]

## 完成情况

### 后端 ✅
- 实现 API:
  - POST /api/v1/mobile/favorites
  - DELETE /api/v1/mobile/favorites/{id}
  - GET /api/v1/mobile/users/{id}/favorites
- 创建表: user_favorites
- 编写测试: 12 个单元测试

### 移动端 ✅
- 新增页面: 我的收藏页面
- 修改页面: 场景详情页（添加收藏按钮）
- 新增文件: 5 个

### 管理后台 ✅
- 新增功能: 用户收藏统计
- 修改文件: 3 个

## 统计数据
- 总文件数: 18 个
- 总代码行数: ~800 行
- 测试数量: 12 个
- 总耗时: 25 分钟（自��化）

## 后续建议
- [ ] 添加收藏数量限制
- [ ] 实现收藏分类功能
- [ ] 添加收藏导出功能
```

## 🚨 Important Notes

### 必须遵守的规则

1. **理解优先**: 不确定需求时，必须先提问确认
2. **依赖识别**: 必须正确识别任务依赖关系
3. **优先级判断**: 合理设置任务优先级
4. **三端协调**: 确保三端数据模型和接口一致
5. **进度跟踪**: 实时更新任务状态

### 常见场景处理

**场景 1: 用户需求模糊**
```
用户: "优化场景功能"
→ 提问: "您指的是哪方面的优化？性能/UI/功能？具体是移动端还是管理后台？"
```

**场景 2: 跨端功能**
```
用户: "实现用户收藏"
→ 识别: 移动端（用户功能）+ 管理后台（统计）+ 后端（API）
→ 分解: 3 个任务，后端优先
```

**场景 3: 仅后端功能**
```
用户: "添加 API 限流"
→ 识别: 仅后端
→ 分解: 1 个任务
```
