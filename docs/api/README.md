# API 文档规范

## 目录结构

```
docs/api/
├── README.md          # API 文档规范说明（本文件）
├── endpoints/         # API 端点文档
│   ├── auth.md       # 认证相关接口

    ├── common.md     # 通用数据结构
    └── ...           # 其他数据模型
```

## 文档编写规范

### 1. 接口文档模板

每个接口必须包含以下信息：

```markdown
## 接口名称

**接口描述**：简要说明接口功能

**请求方式**：GET | POST | PUT | DELETE

**接口路径**：`/api/v1/xxx`

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| id     | string | 是 | 资源ID | "scene_001" |

**请求示例**：

```json
{
  "id": "scene_001"
}
```

**响应参数**：

| 参数名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| success | boolean | 操作是否成功 | true |
| message | string | 响应消息 | "success" |
| data | object | 响应数据 | {...} |

**响应示例**：

```json
{
  "success": true,
  "message": "success",
  "data": {
    "scene": {
      "id": "scene_001",
      "name": "场景名称"
    }
  }
}
```

**错误码说明**：

| 错误码 | 说明 | 处理建议 |
|--------|------|----------|
| 401 | 未授权 | 需要重新登录 |
| 404 | 资源不存在 | 检查请求参数 |
```

### 2. 文档更新要求

**重要规则：每次开发新功能时，必须同步更新 API 文档**

- **新增接口**：在对应模块的文档中添加完整的接口说明
- **修改接口**：更新相关接口的参数、响应或说明
- **删除接口**：标记为已废弃，并说明替代方案

### 3. 前后端协作流程

1. **接口设计阶段**：后端先编写 API 文档，定义接口规范
2. **评审确认**：前后端共同评审接口文档，确保符合需求
3. **并行开发**：
   - 前端：根据 API 文档进行开发和 mock 数据
   - 后端：根据 API 文档实现接口
4. **联调验证**：前后端联调时，以 API 文档为标准验证接口一致性
5. **文档同步**：接口有任何变更，必须立即更新文档并通知对方

### 4. 响应格式统一规范

所有接口响应必须遵循统一格式：

**成功响应**：
```json
{
  "success": true,       // 操作是否成功
  "data": {},            // 业务数据
  "message": "success"   // 响应消息
}
```

**失败响应**：
```json
{
  "success": false,      // 操作是否成功
  "errorcode": 404,      // 错误码（失败时存在）
  "message": "错误描述"   // 错误消息
}
```

> **注意**：HTTP 状态码根据错误码自动映射（200成功、400参数错误、401未授权、404不存在、500服务器错误等）

### 5. 文档维护责任

- **后端开发**：负责编写和维护 API 文档
- **前端开发**：发现文档与实际不符时，及时反馈并协助更新
- **Code Review**：每次 PR 必须检查是否同步更新了 API 文档

## 常见问题

### Q: 什么时候需要更新 API 文档？

A: 以下情况必须更新文档：
- 新增接口
- 修改接口路径、请求方法
- 修改请求参数或响应参数
- 修改响应数据结构
- 接口废弃或删除

### Q: 如何保证文档和代码一致？

A: 
1. 在开发前先写文档（文档驱动开发）
2. PR 时必须检查文档更新
3. 定期进行文档和代码的一致性检查
4. 使用工具自动生成部分文档（如 Swagger）

### Q: 接口文档放在哪里？

A: 统一放在 `docs/api/endpoints/` 目录下，按功能模块分类
