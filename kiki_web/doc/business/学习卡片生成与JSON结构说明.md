# 学习卡片生成与 JSON 结构说明

> 版本：v1.1 | 创建日期：2026-05-12

---

## 1. 概述

每个**场景 (Scene)** 包含一张大图（`interactive_image`）和若干可点击的**学习区域 (Region)**。
用户在移动端进入场景详情页后，点击图片上的某个物品区域，右侧面板会展示对应的**学习卡片**（中文汉字笔顺 + 英文四线格 + 朗读按钮）。

---

## 1.1 场景图片生成 Pipeline（端到端流程）

### 整体流程

```
Step 1: 确定场景主题
    │   例：图书馆、厨房、动物园
    ▼
Step 2: 确定学习词汇表（6~10 个）
    │   每个词：中文 + 拼音 + 英文 + 音标
    ▼
Step 3: 用 Banana (Google AI) 生成场景图片
    │   输入：场景主题 + 词汇列表 + 生成 Prompt
    │   输出：一张带标注的学习卡片图（含标题 "Hi Kiki"、物品插图、箭头指示）
    ▼
Step 4: 根据生成的图片标注热区坐标
    │   方法：人工标注 / 图像识别辅助
    │   输出：每个物品在图片上的 4 点矩形坐标
    ▼
Step 5: 组装 JSON 数据
    │   将词汇信息 + 坐标合并为 items_data JSON
    ▼
Step 6: 上传到后台
    │   图片 → CDN
    │   JSON → scene.items_data 或 scene_items 表
    ▼
Done: 移动端可展示并交互
```

### Step 2 — 词汇表模板

每个场景准备 6~10 个学习词汇，格式：

| 序号 | 中文 | 拼音 | 英文 | 音标 |
|------|------|------|------|------|
| 1 | 书 | shū | Book | /bʊk/ |
| 2 | 笔 | bǐ | Pen | /pɛn/ |
| ... | ... | ... | ... | ... |

### Step 3 — Banana 图片生成规范

**图片构成要素**：
- 标题区域：顶部显示 "Hi Kiki"
- 物品区域：6~10 个物品的卡通插图，均匀分布在画面中
- 标注区域：每个物品旁边有箭头 + 文字说明（中英文）
- 整体风格：儿童友好、色彩明亮、卡通插画风

**图片输出要求**：
- 分辨率：建议 1536×2048 或类似竖版比例
- 格式：PNG（保留清晰度）
- 物品之间留有足够间距（便于后续热区标注不重叠）

**Banana Prompt 模板**：（待补充用户实际使用的 Prompt）

```
[用户提供的 Banana prompt 将填入此处]
```

### Step 4 — 热区坐标标注

拿到生成的图片后，需要为每个物品标注矩形热区（4 个顶点坐标）。

**标注方法**：
1. 用图片编辑工具打开图片，记录每个物品的左上角和右下角像素坐标
2. 计算 4 个顶点：`(x1,y1), (x2,y1), (x1,y2), (x2,y2)`
3. 确保热区覆盖物品主体 + 适当留白（方便点击）
4. 相邻热区不重叠

**坐标参照系**：
- 原点 (0,0) 在图片左上角
- x 轴向右，y 轴向下
- 单位：像素（基于原始图片尺寸）

### Step 5 — JSON 组装

将词汇表 + 坐标合并，生成最终 JSON（格式见下方第 3 节）。

## 2. 数据层级关系

```
分类 (Category)
 └── 场景 (Scene)
      ├── interactive_image   ← 场景大图 URL
      └── items_data          ← JSON 数组，定义所有可点击区域
           └── Region 对象 × N
                ├── 中文 (text)
                ├── 拼音 (text_pinyin)
                ├── 英文 (text_english)
                └── 坐标 (coordinate) ← 4 个顶点，定义点击热区
```

---

## 3. items_data JSON 结构

场景的 `items_data` 字段存储一个 JSON 数组，每个元素代表图片上的一个可点击区域。

### 3.1 完整字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 区域类型，固定值 `"chinese"` |
| `id` | string | 是 | 唯一标识，格式 `"label_chinese_{序号}"` |
| `index` | int | 是 | 显示顺序，从 1 开始 |
| `text` | string | 是 | 中文名称，如 `"餐桌"` |
| `text_pinyin` | string | 是 | 拼音（带声调），如 `"cān zhuō"` |
| `text_english` | string | 是 | 英文名称，如 `"Table"` |
| `text_phonetic` | string | 是 | 英文音标（IPA），如 `"/ˈteɪbl/"` |
| `coordinate` | array | 是 | 4 个坐标点，定义矩形热区（基于原图像素） |

### 3.2 coordinate 坐标说明

坐标数组包含 **4 个顶点**，按以下顺序排列：

```
点1 (左上) ──── 点2 (右上)
   │                │
   │     热区区域     │
   │                │
点3 (左下) ──── 点4 (右下)
```

- `x`、`y` 值为**原始图片上的像素坐标**（非屏幕坐标）
- 前端会根据图片缩放比例自动换算为屏幕坐标

### 3.3 单条 Region 示例

```json
{
  "type": "chinese",
  "id": "label_chinese_01",
  "index": 1,
  "text": "餐桌",
  "text_pinyin": "cān zhuō",
  "text_english": "Table",
  "text_phonetic": "/ˈteɪbl/",
  "coordinate": [
    { "x": 510, "y": 633 },
    { "x": 726, "y": 633 },
    { "x": 510, "y": 771 },
    { "x": 726, "y": 771 }
  ]
}
```

```json

    "id": "label_chinese_01",
    "index": 1,
    "text": "餐桌",

    "text_phonetic": "/ˈteɪbl/",
    "coordinate": [
      { "x": 510, "y": 633 },
      { "x": 726, "y": 633 },
```

## 4. 图片生成规范

### 4.1 场景大图要求

| 属性 | 要求 |
|------|------|
| 格式 | JPG / PNG |
| 风格 | 卡通/插画风格，色彩明亮，适合儿童 |
| 内容 | 一个完整的场景画面，包含 10-12 个可识别的物品 |
| 物品要求 | 每个物品在画面中清晰可辨，不重叠遮挡，留有足够空间标注热区 |

### 4.2 热区标注规则

1. **每个物品一个热区**：一个 Region 对应图片中的一个物品
2. **矩形区域**：用 4 个顶点坐标框选物品的可视范围
3. **不重叠**：相邻物品的热区之间不应重叠
4. **覆盖主体**：热区应完整覆盖物品的主体部分
5. **适当留白**：热区比物品略大一圈，方便用户点击

## 5. 点击交互流程

```
用户点击图片上某个物品区域
        │
        ▼
前端判断点击坐标落在哪个 Region 内
        │
        ▼
设置 activeRegion = 该 Region
        │
        ├──▶ 右侧面板显示学习卡片
        │    ├── 中文汉字（带笔顺动画）
        │    ├── 英文四线格
        │    └── 朗读按钮
        │
        └──▶ TTS 自动朗读
             ├── 中文发音
             └── 英文发音
```

点击某个区域后，右侧面板展示的内容：

| 区域 | 展示内容 | 数据来源 |
|------|----------|----------|

---

## 7. 数据加载优先级

前端加载 Region 数据的优先级：

1. **`scene.items_data`**（API 返回的嵌入式 JSON 数组）→ 最高优先
2. **`scene.data_file`**（远程/本地 JSON 文件路径）→ 次选
3. **默认本地文件** `assets/data/kiki_zhiwuyuan.json` → 兜底

---

## 8. 后端数据库对应

### scenes 表

| 字段 | 类型 | 说明 |
|------|------|------|
| `interactive_image` | TEXT | 场景大图 URL |
| `items_data` | JSONB | Region 数组（同上述 JSON 结构） |

### scene_items 表

| 字段 | 类型 | 说明 |
|------|------|------|
| `item_type` | VARCHAR | 默认 `"chinese"` |
| `item_index` | INTEGER | 排序序号 |
| `text` | VARCHAR | 中文名称 |
| `text_pinyin` | VARCHAR | 拼音 |
| `text_english` | VARCHAR | 英文名称 |
| `coordinates` | JSONB | 4 个顶点坐标数组 |

> `scene_items` 表为独立的物品行存储，`items_data` 为嵌入式 JSON 存储。两者内容一致，前端优先使用 `items_data`。
