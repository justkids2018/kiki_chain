**自动激活条件**:
- 用户要求自动执行任务时

- 定时执行（如果配置了定时任务）

**触发关键词**:
- "自动执行任务"

## 📋 Workflow / Process

### Step 1: 扫描任务池

**目标**: 读取所有待执行的任务

**任务池位置**:
- `docs/tasks/backend/backlog.md` - 后端任务池
- `docs/tasks/app/backlog.md` - 移动端任务池
- `docs/tasks/admin/backlog.md` - 管理后台任务池
- `docs/tasks/backend/features/*.md` - 具体任务文件
- `docs/tasks/app/features/*.md` - 具体任务文件
- `docs/tasks/admin/features/*.md` - 具体任务文件

**扫描逻辑**:
1. 读取所有 backlog.md 文件
2. 提取待办任务列表
3. 读取具体任务文件（.md）
4. 解析任务元数据：
   - 优先级（P0/P1/P2/P3）
   - 状态（📝 待办/🚀 进行中/✅ 完成）
   - 涉及端（后端/移动端/管理后台）
   - 预计时间
   - 依赖关系
   - 是否允许自动执行

**过滤条件**:
- [ ] 状态为"📝 待办"
- [ ] 允许自动执行（`是否允许自动执行: [x] 是`）
- [ ] 依赖任务已完成
- [ ] 符合优先级要求（如果指定）

### Step 2: 分析任务依赖

**目标**: 构建任务依赖图，确定执行顺序

**依赖类型**:

1. **显式依赖**: 任务文件中明确声明
   ```markdown
   ## 依赖关系
   - 依赖: 用户认证 API（必须先完成）
   - 依赖: 数据库迁移（必须先完成）
   ```

2. **隐式依赖**: 根据任务类型推断
   - 后端 API → 前端集成（后端必须先完成）
   - 数据库设计 → 后端实现（数据库必须先完成）
   - 契约定义 → 代码生成（契约必须先完成）

3. **技术依赖**: 根据技术栈推断
   - Entity 定义 → Repository 实现
   - Use Case → Handler → Routes

**依赖图示例**:
```
[数据库: 创建 scenes 表] (P0)
         ↓
[后端: Scene API 实现] (P0)
         ↓
         ├→ [移动端: 场景列表页面] (P1)
         └→ [管理后台: 场景管理] (P1)
```

**执行策略**:
- **串行执行**: 有依赖关系的任务按顺序执行
- **并行执行**: 无依赖关系的任务可以并行
- **优先级排序**: 同级任务按 P0 > P1 > P2 > P3 排序

### Step 3: 生成执行计划

**目标**: 生成详细的执行计划，展示给用户确认

**执行计划格式**:
```markdown
## 📋 执行计划

### 任务总览
- 总任务数: 8
- P0 任务: 3
- P1 任务: 3
- P2 任务: 2
- 预计总时间: 12 小时

### 执行阶段

#### Phase 1: 基础设施（串行）
1. [P0] 数据库迁移: 创建 scenes 表 (0.5h)
2. [P0] 契约定义: Scene 契约 (0.5h)
3. [P0] 代码生成: 从契约生成代码 (0.1h)

#### Phase 2: 后端实现（串行）
4. [P0] 后端: Scene CRUD API (3h)
   - 依赖: Phase 1 完成

#### Phase 3: 前端实现（并行）
5. [P1] 移动端: 场景列表页面 (2h) ║
6. [P1] 管理后台: 场景管理界面 (2h) ║
   - 依赖: Phase 2 完成

#### Phase 4: 优化和测试（并行）
7. [P2] 性能优化: 场景列表缓存 (1h) ║
8. [P2] 集成测试: 端到端测试 (2h) ║

### 执行顺序
```
Phase 1 (串行) → Phase 2 (串行) → Phase 3 (并行) → Phase 4 (并行)
预计总耗时: 8.1h（考虑并行执行）
```

### 确认执行
是否立即执行此计划？ [是/否]
```

### Step 4: 执行任务

**目标**: 逐个执行任务，调用相应的 skills

**执行流程**:

对于每个任务：

1. **更新任务状态**: 📝 待办 → 🚀 进行中
2. **识别任务类型**: 根据任务内容识别需要调用的 skills
3. **调用 skills 链**:
   ```
   契约定义任务:
     → /contract-manager

   代码生成任务:
     → /code-generator

   后端实现任务:
     → /contract-manager (如果需要)
     → /code-generator (生成框架)
     → kiki_server/code-implementation (补充逻辑)
     → kiki_server/code-review (审查)

   前端实现任务:
     → /code-generator (生成框架)
     → kiki_web/code-implementation (实现 UI)
     → kiki_web/code-review (审查)

   全栈功能任务:
     → /orchestrator (任务分解)
     → /contract-manager (契约定义)
     → /code-generator (代码生成)
     → 后端实现流程
     → 前端实现流程（并行）
   ```

4. **错误处理**:
   - 如果任务执行失败，标记为 ❌ 失败
   - 记录错误信息
   - 询问用户是否继续执行后续任务
   - 如果有依赖此任务的其他任务，暂停执行

5. **进度更新**:
   - 实时更新任务文件中的状态
   - 显示执行进度（如 [3/8] 完成）

## 🚨 Important Notes

### 任务文件格式要求

任务文件必须包含以下字段：

```markdown
**优先级**: P0/P1/P2/P3
**状态**: 📝 待办 / 🚀 进行中 / ✅ 完成
**涉及端**: 后端 / 移动端 / 管理后台

## 自动化执行
是否允许自动执行？ [x] 是 [ ] 否
```

### 依赖声明

清晰声明依赖关系：

```markdown
## 依赖关系
- 依赖: 用户认证 API（必须先完成）
- 依赖: 数据库迁移（必须先完成）
```

### 安全检查

- [ ] 不执行危险操作（删除生产数据、强制推送等）
- [ ] 不跳过代码审查
- [ ] 不覆盖未提交的代码
- [ ] 失败时暂停执行
